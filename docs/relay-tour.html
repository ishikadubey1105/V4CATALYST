Relay

A handoff is a transaction the system can refuse.

Relay checks a case for missing context, unowned work and undocumented decisions before responsibility moves. The new owner accepts a fingerprinted package, and every step lands in a history that shows if anyone edits it later. This page walks through the product as it is built today, and the plan for what is left.

    A live log for an ongoing complaint

    Owner, manager, assignees, the incoming owner and the auditor can all post what happens as it happens. Each entry shows its author's role. Try posting one.

    • Auditors can post here but stay read-only everywhere else.
    • Posting stays open during a handoff. The case does not pause.
    • The receiver sees anything posted after the package was sent, flagged separately.
    • Each entry notifies the people carrying the case.

      How it fits together

      One app, two managed services

      The browser talks to one Next.js app. Every request is checked for role before anything happens, and every change writes its history entry in the same database transaction.

      Web

      Browser, four roles

      • Member: owns and hands off cases
      • Manager: sees the team, can reassign
      • Auditor: read-only, verifies history
      • Admin: sets the gate rules

      Signed session cookie over HTTPS →

      Next.js on Vercel

      Relay app

      authorize() role check on every route
      evaluate() the readiness gate, 12 rules
      appendLog() chained history, same transaction
      verifyChain() recomputes every hash
      Cloud

      Managed storage

      • Postgres on Neon: cases, history, handoffs
      • Vercel Blob: documents, fingerprinted
      • Vercel Cron: overdue sweep

      Local development uses SQLite and disk.
